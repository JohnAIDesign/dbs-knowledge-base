# 海顺第二版实施建议：质量、交付期、成本一起落到流程

本版以您最新确认的三项重点为准：产品质量、交付期、成本控制。此前提出的库存周转保留为支撑指标，不再单列为第四项战略主轴。以下是实施设计，不是对海顺现有业绩或根因的判断；所有实际目标值、人员和日期需基于业务资料确定。

## 1. 总经理先做的选择

建议把首轮DBS组织成“一个产品族、一位端到端负责人、三个结果、一个日周月节奏”。一个试点是当前能力条件下的起步建议，不是DBS的普遍规定。

QDC是需要改善的结果方向，本身还不是完整战略。班子先回答：哪个客户群和产品族最值得优先改善？客户最在意哪项质量特性及哪种交期承诺？我们要靠什么能力取得优势？改善的经济价值是否值得投入？本轮暂缓哪些工作？

首轮不要求同时把三项都做到极致。批准一个主要改善假设，同时为另外两项设边界并监测。若有当前严重质量风险，先依现有质量制度遏制、隔离和授权处理；这不意味着其他流程必须等质量全面改善后才启动。

**建议的年度突破表述骨架：**在【产品族/客户群】建立可重复的质量保证与可靠交付能力，在满足【客户质量要求】及【交付承诺】的同时，将【质量损失/可控过程成本】由【基线】改善至【经批准目标】。具体数字应在基线核实、原因诊断和资源协商后批准。

## 2. 从战略到现场的部署链

| 层次 | 海顺要回答什么 | 实际工作产物 | 不能混用 |
|---|---|---|---|
| 客户与战略选择 | 为谁改善，哪些质量/交付要求最重要，为什么现在做 | 一页客户与业务差距说明，明确不做什么 | QDC三个词不等于战略 |
| 年度突破 | 今年必须形成什么能力和结果 | 三项结果基线、目标范围、期限和依据 | 不能拿培训或上线系统当年度经营结果 |
| 优先改善IP | 哪项流程机制必须改变 | 一至两项初选流程改善，经诊断再确认 | 一个改善可以同时支持Q、D、C |
| TTI | 如何知道这个流程真的改善 | 有口径、数据来源、基线、目标轨迹的效果指标 | 不是“开会/培训/完成方案” |
| 资源协商 | 谁主责，谁支持，需要停下什么 | 明确时间、权限、依赖和升级路径 | 矩阵圆点不等于资源可用 |
| 现场行动 | 改哪个步骤、参数、信号或接口 | 调查/试验/实施任务，逐项负责人和接受条件 | 未验证原因不能写成既定事实 |
| 日常运行 | 什么是正常，异常谁响应 | 标准、实际、偏差、响应和升级看板 | 有看板不等于DM在运行 |
| 经营与能力评审 | 效果、代价和人员能力是否达标 | 继续/修改/停止/标准化/复制的决定 | 不把任务完成率等同收益兑现 |

这条链需反复往返。诊断可能改变优先改善，试验可能否定因果假设，资源不足可能要求缩小范围。PD部署与试点DM可并行建立；这与LEI对二者关系的解释一致。[LEI：战略执行与日常管理](https://www.lean.org/the-lean-post/articles/executing-strategy-through-daily-management/)

## 3. 首轮选哪条产品族

先比较2—3个候选，避免凭音量最大的部门决定。每个候选写清以下事实，不先拼一个主观总分：

1. 客户影响：客户投诉、退货、欠交或交期不稳定的实际证据。
2. 经济损失：报废、返工、加急、额外检验、占用等能够追溯的记录。
3. 流程边界：订单/工艺/物料/生产/检验放行/发运有哪些跨部门接口。
4. 可观察性：有没有足够业务量、原始记录和合理观察周期。
5. 可改变性：负责人能否调动需要的资源并在试点范围试行。
6. 代表性与风险：是否覆盖常见产品路线；是否含必须独立处理的重大风险。

选客户影响重要、边界可控、能在合理周期观察学习结果的一条。不要仅挑最容易做出漂亮数字的流程，也不把无法在90天完成客户验证的新品项目硬塞入短周期验收。

## 4. 一个团队对同一结果负责

| 角色 | 必须承担的工作 | 验收证据 |
|---|---|---|
| 总经理/业务赞助人 | 选择试点、批准目标与资源、协调冲突、示范现场问证据 | 有取舍的决定、障碍解除、按期评审 |
| 端到端流程负责人 | 对三项结果、跨职能行动与日常维持负责 | 能追溯一次订单及一次缺陷的全链路 |
| 质量/工艺 | 定义关键质量要求、测量方式、验证和放行条件 | 缺陷定义一致、验证记录、受控标准 |
| 计划/生产/采购 | 识别约束、物料缺口、换型、排程与供应条件 | 实际时间与异常证据、可信计划 |
| 销售/客户接口 | 确认需求、承诺基准与变更，反馈客户结果 | 原始要求、承诺及变更记录 |
| 财务/数据支持 | 核实损失、成本口径和收益类型 | 可复算基线、成本变化分解、无重复记账 |
| DBS教练/内部骨干 | 示范方法、现场纠偏、逐步让负责人独立主持 | 团队会做，不是教练替团队填完 |

角色可由现有人员兼任。质量批准权限与现行职责不因试点被取消。首轮不必先设完整DBS办公室，先明确谁承担教练功能及可用时间。

## 5. 指标：三项结果，少量驱动因素

所有分母、单位、排除规则、变更记录和统计截点在试点开始时冻结为基准版本。指标“过程/结果”是相对目标而言，不是永久标签。建议首轮看板只放5—7项，下面是备选字典，不要求全部上墙。

| 指标 | 建议定义 | 使用与陷阱 |
|---|---|---|
| Q：客户质量表现 | 同批/同期间范围下的确认不合格交付量÷对应交付量；件、重量、面积选择适用且一致的单位 | 投诉率、退货率与外部PPM分别定义；不能把投诉次数当缺陷件数。PPM需要再乘10⁶；滞后投诉应回溯批次，另看开放问题 |
| Q：一次通过率FPY | 指定工序不经返工即合格的数量÷进入该工序数量 | 固定工序、产品族、单位和观察窗口；跨工序整体一次通过另行追踪，勿简单平均 |
| D：准时足量交付OTIF | 本期到期、按约定时间及数量完整兑现的订单行数÷本期全部到期订单行数 | 提前约定按发运还是客户收货、容差和部分交付规则；未交付仍在分母。OTD如不含数量，需明确与OTIF区别 |
| D：交付周期 | 约定订单受理点到约定完成点的时长 | 同时列中位数、P90与未完成订单账龄，防止只统计已完成的快单。原请求日期和承诺日期同时保留 |
| C：质量损失成本 | 约定范围内报废、返工和其他不良质量损失的实际金额，分项登记 | 一项损失只记一次；另看每合格单位损失。估算机会损失与已发生支出分列 |
| C：可控单位过程成本 | 同一范围可控过程成本÷合格产出量 | 产品组合、价格、产量变化分解后比较；以财务核定口径为准，不用降质量或多生产摊薄成本 |
| 支撑：在制品与库存 | 按原料/在制品/成品、地点、质量状态、库龄分层的数量与金额 | 看全边界总量，转到供应商/别的车间不算消除；滞销核销不当作现金释放 |
| 支撑：库存周转天数 | 同范围期间平均库存成本÷同期间销货成本×期间天数 | 期间与范围一致，分母为零不算；短期经营看板同时看实物和库龄，不靠销量上涨掩盖库存问题 |
| 选用：计划兑现/齐套/换型 | 由已验证的主要差距决定口径 | 不是三项全上；“排程变更少”不能以拒绝合理客户需求取得 |

日常DM与PD可以引用同一OTIF数据源：DM看今天的承诺与异常，PD看年度提升轨迹及新机制是否有效。不要再为PD造一套不同口径的交付率。

## 6. 前两周怎样取证

**先拉数据，再到现场核对它是否代表实际。**建议提取最近8—12周的记录作为起点；有季节性、低业务量或长周期时扩展，不把该长度当统计充分性的保证。

| 数据包 | 最低字段 | 谁核对 |
|---|---|---|
| 订单与交付 | 订单行/产品族/数量/原请求日期/首次确认承诺/变更及原因/实际发运和到货/未交数量 | 销售、计划、仓储共同核对 |
| 质量与流转 | 批次/工序/投入与合格量/缺陷种类/发生与检出点/返工报废/放行状态及时间 | 质量、工艺、生产 |
| 时间与损失 | 排队/生产/换型/停机/检验/放行/运输时间，额外加班与加急 | 流程负责人、财务 |
| 库存与物料 | SKU/地点/数量金额/库龄/可用或隔离状态/在途/供应周期/MOQ/订单绑定 | 仓储、采购、计划 |
| 现有管理 | 已填PD矩阵、目标表、行动计划、标准、异常记录及会议决定 | 经营班子、负责人 |

从典型正常订单、延期订单、返工批次和高龄库存各选真实记录走访，先打通记录之间的关联；样本用于发现线索，不直接宣称代表总体。记录无法连接时，本阶段产出应是修复数据与追踪方式，而非精确收益承诺。

## 7. 按证据选工具，不一次铺开

| 发现的主要机制（必须先验证） | 优先调用 | 应改变什么 | 同时验收 |
|---|---|---|---|
| 缺陷/返工拖长周期 | PSP、测量核对、过程控制、标准作业 | 发生条件及防错/反应规则 | 缺陷、返工、周期和成本 |
| 等待审批或信息反复补充 | VSM、TPI、输入标准 | 信息一次完整、权限及异常交接 | 等待时间、一次齐套、客户承诺 |
| 批量大、换型长、队列长 | VSM、SMED、受控小批量试验 | 换型方法、批量与释放规则 | 首件质量、交付、总损失成本 |
| 需求/供应不稳导致缺料和堆货 | PSI协同、分层补货、供应问题解决 | 服务策略、计划假设与补货参数 | 缺货、库存、OTIF、加急成本 |
| 故障反复打断关键工序 | 设备故障分析与维护 | 重点故障机制及点检维护 | 实际可用能力、质量和交付 |

拉动不意味着所有SKU都设相同库存，也不意味着取消预测和能力规划。选用补货或顺序拉动应与需求、品类数量和交期条件匹配。[LEI：拉动生产](https://www.lean.org/lexicon-terms/pull-production/)

减少缓冲前先检查需求变异与供给能力；若二者未改善，直接砍库存可能恶化交付。[LEI：库存](https://www.lean.org/lexicon-terms/inventory/)

## 8. 90天路线：按证据过关

| 阶段 | 团队实际做什么 | 总经理作什么决定 | 通过条件 |
|---|---|---|---|
| 启动—第2周 | 选产品族、统一质量/交付/成本口径，现场跟单，核实基线，形成现状价值流 | 范围、主责、可用时间、待暂停工作、客户及质量边界 | 他人可以复算主要指标；至少一条真实订单/批次全链可追溯；未知数据明确列出 |
| 第3—4周 | 分层关键损失，验证原因，选择一个优先改善；搭建最小异常响应节奏 | 批准试验边界、资源、停止条件及目标假设 | 原因有证据；预期作用与衡量方法写清；负责人能独立解释逻辑 |
| 第5—8周 | 小范围试行，跨班次/批次观察QDC与副作用；修订方法和标准，现场带教 | 继续、修改或停止；解除跨部门障碍 | 看得到预期机制的改变；无不可接受的Q/D/C恶化；试验记录完整 |
| 第9—12周 | 固化有效方法，验证替代人员；复核结果、成本和保持条件 | 批准维持、继续试验或第二试点 | 覆盖约定业务周期、波动与关键条件；标准有人维持、异常有人处理、收益无重复计算 |

日期是计划窗口，不是强制毕业日。第12周未形成稳定证据就继续验证，不能为按期结项宣布成功。前两周发现问题和第一个月看板运行都不等于年度目标完成。

**6—12个月：**在首轮机制和能力验证后，按相似约束选择下一产品族；每次只增加团队能承受的范围；季度复核客户要求、产品组合和资源。可以共享原理、数据定义和带教方法，补货参数、批量、工艺条件必须本地验证。若首轮不能独立维持，优先补负责人和日常节奏，不扩范围。

## 9. 固定节奏及每次必须产出的东西

以下时长为起步建议，可并入现有会议；不额外叠加一套会议体系。

| 频率 | 谁主持 | 只处理哪些问题 | 必须留下 |
|---|---|---|---|
| 每班/每日，10—15分钟 | 现场/计划主管 | 当日质量风险、到期交付风险、阻塞，是否需要遏制或升级 | 谁、何时、做什么；重大问题不等下次会议 |
| 每周，45—60分钟 | 端到端负责人，教练带教 | 主要差距、原因证据、试验、跨部门依赖 | 继续/修改/停止动作与资源请求 |
| 每月，60—90分钟 | 总经理/赞助人 | QDC趋势、收益性质、资源取舍和人员独立能力 | 明确经营决定、主责与复核日期 |
| 阶段结束，15—30分钟 | 负责人 | 原计划、事实、学到什么、更新什么 | 一页AAR；必要时并入周会 |

总经理的五个固定问题：客户差距是什么？证据在哪里？哪个原因还没验证？需要我作什么决定？教练不在时谁能按标准运行？

## 11. 一个完整演练：返工、延期与成本怎样共用一条改善链

以下仅为方法演练，不是海顺现场事实，也不预设存在具体缺陷。

**现象：**某产品族质量复验与返工多，订单延期，额外加班增加。不能直接下结论“操作员不认真”或“产能不够”。

1. 定义：质量人员写出能一致判定的缺陷与合格要求，确认测量方式；销售与计划确认原承诺；财务确定返工成本范围。
2. 跟流：选择真实批次，把工序、检出、返工、等待、放行和发运连接，核对是否真由返工造成延期，还是另有订单优先级/物料问题。
3. 分层：按产品、班次、设备、工艺条件等适用维度找集中点；柏拉图只决定先查什么，不证明原因。
4. 取证：假设为“换型后关键条件未稳定导致首段不合格”，先验证测量和实际记录；若数据不支持就否定，不先采购设备或全员重训。
5. 对策：只有假设获支持后，才试行经授权的准备、确认或标准调整；明确哪些条件不允许继续、谁作批准。
6. 验收：看缺陷/返工、OTIF、全周期和实际损失成本；若新增检查把等待拉长，需改方案，不能只报质量提升。
7. 保持：有效方法纳入标准与DM，训练替代者，跨适用条件复核；未稳定则不复制。

该例中的IP是“建立稳定的换型与质量确认流程”（仅当原因成立）；TTI是流程效果的量化目标；行动是取证、试验、修改标准与能力验证。三者不能写成同一条“加强质量管理”。

## 12. 下一步启动包

您现在需要批准的是试点选择和取证安排，而不是先批准一个未经基线验证的降本比例。

- 启动前：指定赞助人、端到端负责人和教练；准备两三个候选产品族及数据可用性。
- 90分钟启动会：确认客户与业务问题、选择试点、界定边界；决定人员投入和暂缓事项；批准两周取证计划。
- 第2周结束：审查可复算基线、现状图和主要差距；批准一个试验与临时目标假设。
- 目标定稿：以数据和资源能力为依据，通过上下/横向协商批准QDC目标、TTI及观察周期。现有实际PD矩阵若已有目标，先核对依据，不自动重设。
